Detection-as-Code Pipeline

A from-scratch Python compiler and delivery workflow that turns supported Sigma detection logic into Wazuh-compatible XML, verifies the result, preserves rule identity, and deploys through controlled CI/CD.

Claim, evidence, and boundary

Claim

The pipeline can translate its supported Sigma subset into traceable Wazuh rules and deliver them through a controlled workflow.

Evidence

58 Sigma rules compile to 216 Wazuh rules across 119 ATT&CK techniques, backed by 87 automated tests.

Boundary

It is not a complete Sigma backend. Unsupported value types and oversized DNF expansions fail the build instead of producing uncertain output.

The problem

Wazuh needed more than a format converter.

Wazuh 4.x did not provide an official pySigma backend and could not directly express every boolean structure used by Sigma detections. A useful workflow had to do more than convert YAML to XML. It had to preserve supported logic, reject unsupported logic, keep generated rule IDs stable, validate artifacts, and avoid treating deployment as a blind file copy.

The security relevance is operational. A detection that compiles incorrectly can look deployed while silently missing the behavior it was meant to catch. The project treats translation errors, identity drift, and unsafe deployment as security failures.

Architecture

From source rule to controlled deployment.

  1. 01 / AuthorSigma YAMLSingle source of truth with UUID and ATT&CK tags.
  2. 02 / ParsepySigma ASTSyntax validation and expression tree input.
  3. 03 / CompileDNF and PCRE2Field mapping, De Morgan handling, and Jinja2 XML.
  4. 04 / GateCI validationTests, ID checks, syntax checks, and security scans.
  5. 05 / DeliverWazuh APIDry run, authenticated upload, reconciliation, and restart.

Implementation detail

The compiler walks logic, not strings.

For a rule that requires `certutil.exe` and both `urlcache` and `split` in the command line, pySigma expands the source into an expression tree. The compiler maps Sigma fields to Wazuh decoder fields, translates wildcards into PCRE2, merges same-field positive clauses with lookaheads, and renders the result through Jinja2. 

detection:
    selection:
        Image|endswith: '\certutil.exe'
        CommandLine|contains|all:
            - 'urlcache'
            - 'split'
    condition: selection

The generated XML keeps the Sigma UUID in a comment so the ID validator can prove which source rule produced each artifact. Wazuh rule IDs are stored in `id_registry.json` to prevent unrelated ID changes across builds.

Engineering decisions

Decisions made around failure modes.

Fail loud

Numeric comparisons, regex modifiers, CIDR values, base64 modifiers, field-less keywords, null values, and other unsupported constructs stop the build with a reason. They do not emit a rule that looks valid.

Cap DNF growth

AND distribution is capped at 500 clauses. This prevents pathological boolean expansion from hanging a build or exhausting memory.

Keep IDs stable

A committed UUID-to-ID registry separates detection identity from generation order. CI checks for collisions and missing linkage.

Deploy by diff

Pull requests receive a dry-run deployment diff. Manual deployment authenticates to the Wazuh API, uploads a bundle, and reconciles stale rules behind a blast-radius safeguard.

Secure the pipeline

GitHub Actions are SHA-pinned. Gitleaks, CodeQL, Bandit, pip-audit, Dependabot, and a threat model address the supply chain around the detection pipeline itself.

The deployment path was checked against a live Wazuh 4.9 manager. That verification exposed a real reconciliation bug: the API response used `relative_dirname`, while the original parser expected `path`. The parser and regression tests were updated after the mismatch was observed.

Known limits

What the pipeline does not solve.

  • Incomplete Sigma coverage: Some modifiers and value types are intentionally rejected.
  • Field mapping risk: An unmapped field passes through unchanged. The result may compile but never fire if no Wazuh decoder populates that field.
  • Combinatorial logic: Rules that exceed the DNF cap must be simplified or supported through a different backend strategy.
  • Platform change: Wazuh 5 adds native Sigma support and YAML rules. That reduces the value of the syntax converter, but not the need for validation, testing, safe deployment, and state reconciliation.
  • Dependency exception: The project documents a time-boxed pip-audit exception for a transitive `diskcache` CVE while upstream compatibility is constrained.
