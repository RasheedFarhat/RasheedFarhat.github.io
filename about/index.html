Approach

Build the mechanism. Test the claim. State the limit.

Systems over isolated demos

I gravitate toward projects where the detection logic is only one part of the problem. A useful control also needs inputs, validation, deployment, observability, failure handling, and documentation that another engineer can follow.

Measurement over confidence language

I prefer a bounded result that can be reproduced over a broad claim that cannot. In MCP-DETECT, that means publishing the corpus boundary and evasion gaps next to the false-positive result. In the Sigma pipeline, it means rejecting unsupported constructs rather than emitting uncertain rules.

Security review applies to my own code

A project is not exempt from criticism because I built it. The identity deception case study documents the current webhook-authentication, source-attribution, transport, and failure-handling gaps. Those limits are part of the engineering record.
